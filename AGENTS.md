# AGENTS.md

Notes for agents working in the `rss2email` repo.

## Commands

- Install deps (sync venv from lockfile): `uv sync`
- Update the lockfile after changing deps: `uv lock`
- Run the full test suite (CI's exact invocation):
  ```
  cd test && uv run python -m unittest -v
  ```
  `TestEmails` paths are now derived from `__file__` (paths are globbed
  absolutely and `run_single_test` chdirs locally to the test directory
  for the `feed.run()` call), so the suite also runs from the repo root:
  ```
  uv run python -m unittest discover -s test -t test -p "test*.py"
  ```
- Run a single test class/method:
  ```
  cd test && uv run python -m unittest test.test.TestSend.test_maildir -v
  ```
  (module is `test.test` because `test.py` lives in the `test/` package directory; `cd test` makes the `util/execcontext` import and data paths resolve via this directory being on `sys.path`)
- There is no lint, typecheck, or formatter configured. `unittest` is the only verification step.
- Build sdist/wheel: `uv build`
- Dev shell with all python deps: `uv sync` (installs into the project
  venv from `uv.lock`). The previous `nix-shell` flow has been removed;
  the pinned Nix expressions targeted a 2021 nixpkgs that pre-dated
  `uv` and Python 3.6/3.7, and were broken.

## Test suite quirks

- `test/test.py` loads doctests from most `rss2email` submodules via `load_tests` — doctest failures surface as part of `unittest` output.
- `TestEmails` is generated by a metaclass that scans `test/data/*/*.config`; each `*.config` must have a paired `*.expected`. If an expected file is missing the test fails with a message telling you to set `FORCE_TESTDATA_CREATION=1` to regenerate it. Never commit regenerated fixtures without diffing them carefully.
- Output is sanitized before comparison (`clean_result`): `Message-ID`, `User-Agent`, and MIME boundaries are masked. Don't try to make these deterministic.
- `TestFetch` / `TestSend` spawn real `http.server` instances via `multiprocessing`. `test_fetch_parallel` skips on non-UNIX (`UNIX` from `rss2email.feeds`).
- `ExecContext` (in `test/util/execcontext.py`) runs the **repo-root `./r2e` script** (`r2e_path`), not an installed `r2e`. Keep that shim working.

## Entry points & packaging

- Console entry point: `r2e` → `rss2email.main:run` (declared in `pyproject.toml` `[project.scripts]`). The repo-root `r2e` launcher calls `rss2email.main.run()` directly.
- Packaging is PEP 621 `pyproject.toml` built with setuptools (build backend `setuptools.build_meta`). Deps: `feedparser>=6.0.5`, `html2text==2020.1.16`. `html2text` is pinned because the email-fixture tests (`test/data/*/*.expected`) encode its exact rendering; upgrading it regenerates fixtures — diff carefully before bumping.
- Version is `dynamic` in `pyproject.toml`, read via `tool.setuptools.dynamic.version = {attr = "rss2email.__version__"}`. Source of truth remains `__version__` in `rss2email/__init__.py`.
- Supported Python range: CI matrix is 3.8–3.13 (`requires-python = ">=3.8"`).
- The `setup.py` legacy file has been removed; `pyproject.toml` + `uv.lock` are now the sole packaging/lock source of truth.

## Release flow

- Documented in `HACKING.md`: `uv sync`, run `update-copyright` (config in `.update-copyright.conf`, drives the per-file author/year headers in every source file), update `CHANGELOG`, bump `__version__` in `rss2email/__init__.py`, commit, then build sdist/wheel with `uv build` and `twine upload`. The release flow no longer depends on Nix (the previous Nix expressions were broken; see `HACKING.md`).

## Conventions

- Every source file carries a GPL-2+ header managed by `update-copyright` from `.update-copyright.conf`. When you add a new `.py` file, expect that tool to want a header; don't hand-edit author lines.
- `post_process/` is a subpackage containing pluggable post-process hooks (`downcase`, `prettify`, `redirect`); new hooks go here.
